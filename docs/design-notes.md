# Design notes

Records the reasoning behind features that were deliberately left out, decisions already resolved, and known limitations — so the context isn't lost.

## Items

- **Remote SSH / Dev Container support** — decided against (2026-07). An `extensionKind: ["ui"]` + download-to-local-temp approach would work in principle, but it roughly doubles the extension's surface (file transfer layer, temp-file lifecycle/GC, progress + cancellation UX), risks regressing the working WSL flow (which depends on running *inside* WSL: `wslpath`, interop PowerShell), and the SSH + UI-extension-host combination can't be covered by CI. VS Code's built-in remote Explorer already has right-click → "Download..." which covers the need — the remote-block error message now points users to it.
- **Cut mode** — decided against for now (2026-07). Linux gnome format supports it trivially (`cut\n` header), Windows needs a `Preferred DropEffect` DataObject, macOS has no native pasteboard cut. Platform inconsistency makes the UX confusing.
- **Marketplace publishing polish** — `icon`, CI `vsce package` check to catch manifest/`.vscodeignore` mistakes. Only relevant if/when publishing.
- **macOS keybinding conflict** — resolved (2026-07): macOS now uses `ctrl+c` via the `mac` field in `contributes.keybindings` (`alt+c` with `editorTextFocus` shadowed Option+C "ç" on international layouts; Ctrl+C is free on macOS since system copy is Cmd+C). An earlier report that Ctrl-combos only captured 1 of N files turned out to be the pasteboard-drop bug (see below), not the modifier.
- **macOS pasteboard drops items on large selections** — resolved (2026-08). `NSPasteboard` hands items to the pasteboard server asynchronously; when `osascript` exits immediately after `writeObjects:`, everything still in flight is discarded. The loss scales with the item count, so it looked probabilistic at 3–5 files but became a hard failure as selections grew (measured on an idle M-series Mac: 12 items → 9, 100 → ~62, 300 → ~170). The original verify+retry fix only masked the small-N case: retrying re-runs an identical, identically racy write, so once the count was large enough every attempt failed and the user just saw `Pasteboard write incomplete`. There is no client-side API to await the drain — `pasteboardItems()` is answered from a process-local cache, so the writing process always reports the full count regardless (which is why the old in-script count check was a no-op that merely bought a few milliseconds). Verified that a plain CPU busy-loop settles it as well as `delay`, i.e. this is wall-clock drain time, not run-loop pumping. Fix: `buildMacPasteboardScript` ends with a count-scaled `delay` (`macSettleSeconds`), and the existing verify+retry stays as a safety net with an escalating delay per attempt. Stress-tested 40/40 clean at 1–300 files, both idle and under 10× CPU load.
- **Folder selected together with its own contents** — resolved (2026-08). A tree view makes it easy to select a folder and items inside it at once, and `extractPathsFromArgs` only deduped exact path matches, so both survived. Every receiver copies each entry independently, so the child was pasted twice (inside the folder and beside it) and appeared twice in the ZIP — once as `dir/a.txt`, once as `a.txt` at the archive root. `pruneNestedPaths` now drops anything covered by a selected ancestor, silently: it is unambiguously what the selection means, so a warning would just be noise. Matching is lexical and case-sensitive even though macOS/Windows filesystems usually aren't — paths from one tree selection always agree on casing, and a false match would silently drop a file the user asked for, which is worse than the duplicate it prevents.
- **Clipboard write timeouts report the selection size** — resolved (2026-08). `runProcess` now rejects with `ProcessTimeoutError`, and `copyPathsToClipboard` turns it into a message naming the item count and suggesting a smaller selection or the ZIP command, instead of the bare `osascript timed out after 10s` that gave the user nothing to act on. The 10s budget is the real ceiling on selection size — measured on an idle M-series Mac, ~12,000 items fit (8.9s) and 15,000 does not; the pasteboard settle delay itself has 7.5x+ margin at every size, so it is never the binding constraint.
- **ESLint** — resolved (2026-07): configured ESLint with TypeScript recommended flat config and added lint checks to CI.
- **Broken symlinks are filtered out** — resolved (2026-07): Switched the `fs.existsSync` filter in `extension.ts` to an async `fs.promises.lstat` check, allowing broken symlinks themselves to be copied by the native backends.
- **KDE Dolphin paste (Linux)** — known limitation (2026-07). The Linux backend only offers the `x-special/gnome-copied-files` target, which Nautilus/Thunar/PCManFM read but Dolphin does not (it wants `text/uri-list` + `application/x-kde-cutselection`). wl-copy and xclip can each serve only a single MIME type per invocation, and spawning two steals selection ownership from the first — offering both targets would need a persistent clipboard helper process. Not worth the surface for now.
